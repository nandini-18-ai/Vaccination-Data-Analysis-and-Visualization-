## 2. What's Inside `vaccination.db`

**16 tables** — 6 dimensions, 2 crosswalks, 5 country-level facts, 3 aggregate-level facts:

| Category | Tables |
|---|---|
| Dimensions | `dim_country`, `dim_antigen`, `dim_disease`, `dim_vaccine_schedule_code`, `dim_aggregate_entity`, `dim_vaccine_concept` |
| Crosswalks (analyst-derived) | `xwalk_antigen_disease`, `xwalk_vaccine_family` |
| Country-level facts | `fact_coverage`, `fact_incidence`, `fact_cases`, `fact_vaccine_introduction`, `fact_vaccine_schedule` |
| Aggregate-level facts | `fact_coverage_aggregate`, `fact_incidence_aggregate`, `fact_cases_aggregate` |

`dim_vaccine_concept` was added during final Phase 1 QA to give the vaccine-family crosswalk a
real, foreign-key-enforced dimension (previously an unenforced repeated text value) — see
`docs/PHASE1_VALIDATION_REPORT.md` Section 17 for the full audit and fix.

**Full column-by-column definitions:** see `docs/DATA_DICTIONARY.md`.

**⚠️ SQLite foreign-key note:** `PRAGMA foreign_keys` is a *per-connection* setting in SQLite, not
persisted in the file. A fresh connection defaults to `OFF`. If you open `vaccination.db` with a
tool that will **write** to it, issue `PRAGMA foreign_keys = ON;` immediately after connecting to
get live constraint enforcement. Read-only tools (e.g. Power BI, DB Browser for SQLite in view
mode) are unaffected.

## 3. How to Rebuild Everything From Scratch

Requires Python 3.12+ with `pandas`, `openpyxl`, and `pyarrow` installed
(`pip install pandas openpyxl pyarrow --break-system-packages` if needed).

Run the 7 stages **in order** from the project root (each stage reads the previous stage's
parquet output and writes its own):

```bash
cd phase1_project

python3 scripts/01_load_raw.py           # reads data/raw/*.xlsx -> data/clean/00_raw_snapshot/
python3 scripts/02_clean_standardize.py  # -> data/clean/01_cleaned/   (+ logs/cleaning_log_rows.json)
python3 scripts/03_build_dimensions.py   # -> data/clean/02_dimensions/
python3 scripts/04_build_crosswalks.py   # -> data/clean/03_crosswalks/ (incl. dim_vaccine_concept)
python3 scripts/05_build_facts.py        # -> data/clean/04_facts/
python3 scripts/06_load_sql.py           # builds sql/vaccination.db from sql/schema.sql
python3 scripts/07_validate.py           # -> validation/PHASE1_VALIDATION_RESULTS.json
```

**Prerequisite:** `data/raw/` must contain the 5 original `.xlsx` files (`coverage-data.xlsx`,
`incidence-rate-data.xlsx`, `reported-cases-data.xlsx`, `vaccine-introduction-data.xlsx`,
`vaccine-schedule-data.xlsx`) exactly as supplied. The pipeline never modifies these files.

### Rebuilding just the database (if you already have the `data/clean/` parquet files)
```bash
python3 scripts/06_load_sql.py
```
This drops and recreates every table from `sql/schema.sql`, then reloads from the parquet
files in `data/clean/02_dimensions/`, `data/clean/03_crosswalks/`, and `data/clean/04_facts/`.
It is **idempotent** — running it any number of times produces identical row counts, never
duplicate accumulation (verified in `docs/PHASE1_VALIDATION_REPORT.md` Section 14).

### Running validation only
```bash
python3 scripts/07_validate.py
```
Runs the full check suite (row counts, PK/FK integrity, duplicates, country/year validity,
numeric sanity, aggregate isolation, crosswalk coverage) against whatever `sql/vaccination.db`
currently contains, and overwrites `validation/PHASE1_VALIDATION_RESULTS.json` with the result.
`docs/PHASE1_VALIDATION_REPORT.md` is a hand-assembled narrative of that JSON output — if you
rerun validation and get different numbers, treat the JSON as authoritative and update the
markdown report to match.

## 4. What NOT to Expect in This Deliverable

Per the project's phased scope, this export contains **no EDA, no Power BI artifacts, and no
answers to the 30 assignment questions** — those are explicitly out of scope for Phase 1 and
have not been started. It also contains **no fabricated data**: several assignment-relevant
variables (gender, education, urban/rural, population density, seasonal/monthly granularity,
vaccine supply, within-country socioeconomic grouping, delivery strategy) are absent from the
source data and remain absent here, as documented in `docs/PROJECT_STATUS.md`.
